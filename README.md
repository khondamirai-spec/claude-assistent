# Telegram Business assistant (Claude Code CLI)

A personal assistant for **your own Telegram account**. The bot connects through
Telegram Business (*Chatbots*). When someone writes to you, it drafts a reply in
your name and in your style, using what `profile.md` says about you.

Replies are generated by the **Claude Code CLI** (`claude -p`) installed next to
the bot, so your **Claude subscription** is used (a `claude setup-token` token).
An Anthropic API key is never used.

## What it does

- **Preview mode is the default** (`AUTO_SEND=false`): drafted replies are only
  printed to the logs (and appended to `data/previews.jsonl`); nothing is sent.
  When you like what you see, set `AUTO_SEND=true` and replies are sent from
  your account.
- **Which chats the bot sees is decided only by Telegram**: *Settings →
  Telegram Business → Chatbots* in the Telegram app. There is no allowlist in
  the code.
- Long polling: no domain, webhook or open port needed.
- Runs on Railway from a private GitHub repo (`Dockerfile`, redeployed on every
  push). Your Mac is only for development and testing.

### Behaviour

| Situation | What happens |
|---|---|
| Business connection of another account | Ignored, with a warning in the log. Claude is not called. |
| Which chats | Whatever you picked in *Telegram Business → Chatbots*. Every chat Telegram delivers is handled. |
| You write in a chat yourself | Your message is added to that chat's history and never answered. The bot stays silent in that chat for `OWNER_TAKEOVER_MINUTES` (15). |
| Messages from bots / the bot's own replies | Ignored (`sender_business_bot` or `is_bot`). |
| The same update delivered twice (also in parallel, also after a restart) | Handled once (`data/seen.json`). |
| Service messages (title changes, pins, ...) | Ignored. Media is described: `[photo] caption`, `[voice message]`, `[sticker] 😀`, ... |
| `/pause` | No replies until `/resume`. Survives restarts. |
| Subscription usage limit | No Claude calls until the reset time from the CLI, or for `LIMIT_COOLDOWN_MINUTES` (30) if unknown. Survives restarts. In auto-send mode you get a message. `/resume` clears it. |
| Timeout, login error, crash | Nothing is sent to the chat. In auto-send mode you get at most one alert per 10 minutes. |
| Claude answers `[SKIP]` (conversation over, just "ok", a sticker) | Nothing is shown or sent. |
| Before an auto-send | Pause, limit and takeover are checked again (you may have written meanwhile), and the business connection is fetched again **from Telegram** (owner, enabled, `can_reply`). If anything is off, nothing is sent and the preview says why. |
| Replies longer than 4000 characters | Sent in 4000-character parts. |

Per-chat history is kept separately for every business connection *and* chat
(`HISTORY_LIMIT`, 30 messages).

### Commands (private chat with the bot)

| Command | Who | Effect |
|---|---|---|
| `/start` | you | Uzbek guide: current mode and state, how to connect, commands, notes |
| `/start` | anyone else | A short Uzbek note: this is a personal bot, write to the owner directly. Claude is not called and nothing about you is revealed. |
| `/pause`, `/resume`, `/status` | you only | Pause, resume (also clears limit and takeover timers), show status |

Anything else people send to the bot directly is silently ignored.

## How Claude is called

One process per reply, without a shell:

```
claude -p --safe-mode --settings '{"disableAllHooks": true, "enabledPlugins": {...: false}}'
       --tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands
       --no-session-persistence --system-prompt-file <0600 temp file>
       --output-format json --effort <CLAUDE_EFFORT> [--model <CLAUDE_MODEL>]
```

- No tools, no MCP servers, no hooks, no plugins (the CLI's built-in plugins are
  switched off by name), no skills, no CLAUDE.md, no auto-memory, no saved
  sessions.
- The conversation goes **only through stdin**; the system prompt and profile
  are in a 0600 temp file in `data/claude-run/` (0700), deleted afterwards, so
  nothing personal shows up in `ps`. The process runs in its own session and the
  whole process group is killed on timeout or cancel.
- `--bare` is **not** used: it ignores the OAuth login, so the subscription would
  not work.
- Child environment: everything starting with `ANTHROPIC_` is removed, as are
  `TELEGRAM_BOT_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN` (from the parent),
  `CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY`, `CLAUDECODE`,
  `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_CODE_SIMPLE`.
  `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` are
  added. `CLAUDE_CODE_OAUTH_TOKEN` is set only from the bot's own settings.
- Token rules: only `sk-ant-oat...` tokens are accepted; an `sk-ant-api...` key
  is rejected. The token is never logged, never put in argv/stdin/prompts, and
  is replaced with `[REDACTED]` in CLI output. If Claude rejects it, the error
  says to run `claude setup-token` again and shows `CLI said: ...` (redacted),
  so you can see why without seeing the token.
- `python bot.py --check-claude` sends a tiny request and fails unless tools,
  MCP servers, plugins and skills are all empty, the key source is not an API
  key, and the provider is first-party.

## Deploy to Railway

1. On a computer with a browser run `claude setup-token`, confirm with your
   subscription account and copy the `sk-ant-oat...` token (valid for 1 year).
2. In @BotFather: `/newbot`, then *Bot Settings → Business Mode* → turn on.
   Get your numeric user id from @userinfobot.
3. Create a **private** GitHub repo and push this code. `profile.md` is baked
   into the Docker image, so the repo must stay private.
4. Railway → *New Project* → *GitHub Repository* → pick the repo.
5. Service → *Variables* → *Raw Editor*:

   ```
   TELEGRAM_BOT_TOKEN=...
   OWNER_ID=...
   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
   AUTO_SEND=false
   ```

   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`,
   `LIMIT_COOLDOWN_MINUTES`, `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`.
   Not needed: `CLAUDE_BIN`, `DATA_DIR`, `PROFILE_PATH`.
6. Volume: right-click the canvas (or Cmd+K) → *Volume* → choose the service →
   mount path exactly **`/app/data`** → *Deploy*. Without a volume, history,
   pause and limit state are lost on every deploy.
7. Logs should show `Bot @... is running`, `Mode: PREVIEW ...` and
   `Claude auth: subscription token from environment variables`. Red lines in
   Railway only mean stderr, not errors.
8. Send `/start` to the bot. Then in Telegram: *Settings → Telegram Business →
   Chatbots* (Telegram Premium needed) → enter the bot's username → choose the
   chats → allow replying. The log shows
   `Business connection ...: user=<id> enabled=True can_reply=True`.
9. When someone writes to you, a `PREVIEW, not sent` block appears in the log.
   When the drafts look right, set `AUTO_SEND=true` in Variables.

Notes:

- Run the bot in **one place only**: two pollers with the same bot token fight
  each other. Do not run `python bot.py` locally while Railway is running it.
- Every push redeploys. Editing `profile.md` also means commit + push.
- Token expired or leaked: run `claude setup-token` again and update the Railway
  variable. Bot token leaked: `/revoke` in @BotFather and update the variable.
- The container clock is UTC; put your city/time zone in `profile.md`.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env && chmod 600 .env     # then edit .env with an editor
.venv/bin/python bot.py --check-claude
.venv/bin/python bot.py --try "Salom, qalesan?"
```

Locally, settings come **only** from `.env`; variables in your shell are
ignored. If `CLAUDE_CODE_OAUTH_TOKEN` is empty, this machine's own `claude`
login is used (fine for testing).

### Commands

| Command | Purpose | Exit codes |
|---|---|---|
| `python bot.py` | run the bot with `.env` | 0, 2 = bad settings or Telegram rejected the bot token |
| `python bot.py --settings-from-env` | container mode: settings from environment variables, which are then removed from the process environment | same |
| `python bot.py --check-claude` | check the Claude CLI setup (no Telegram needed) | 0 ok, 1 check failed, 2 bad settings |
| `python bot.py --try "text"` | draft a reply to a made-up message (no Telegram needed) | 0 ok, 1 Claude error, 2 bad settings |

`--check-claude` and `--try` also work together with `--settings-from-env`.

### Tests

```bash
.venv/bin/python -m pytest
```

The tests run offline: Telegram goes through a recording fake session and
Claude through a fake generator or a fake `claude` script.

### Files

```
bot.py                     entry point (run / --settings-from-env / --check-claude / --try)
assistant/config.py        settings from .env or from the environment
assistant/claude_cli.py    one isolated `claude -p` run per reply
assistant/language.py      uz / ru / en hint
assistant/prompts.py       system prompt and conversation block
assistant/store.py         history, seen messages, runtime state (data/)
assistant/service.py       business message handling, preview / auto-send
assistant/handlers.py      aiogram router and owner commands
profile.md                 about you (fill it in; no secrets)
.env.example               local settings template
Dockerfile, railway.json   Railway deployment
tests/                     offline tests
```

Runtime files in `data/` (0700): `history.json`, `seen.json`, `state.json`,
`previews.jsonl` (0600) and the temporary `claude-run/` directory.
